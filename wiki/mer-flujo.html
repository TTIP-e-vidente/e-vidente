Contenido · Mapa

Lecciones, JSON y colocación automática de nodos

El mapa es data-driven: cada nodo apunta a actividades en JSON; el board las posiciona con un algoritmo sobre la curva del nivel.

Lecciones desacopladas (E1 → E2)

  • Mapa: contenido/mapa/*_mapa.json define nodos y games[]
  • Actividades: packs JSON por modalidad (drag, quiz, vincular, completar palabra)
  • Rejugar lecciones completadas — progreso visible sin bloquear repaso
  • Pantalla “lección terminada” cierra el ciclo con feedback y sonido

Partida compuesta por nodo (E3)

  • ArmadorDePartida construye el plan: N minijuegos en secuencia
  • Patrón de dificultad según índice del nodo (fácil → medio → difícil)
  • JSON con 3–4 games explícitos o pool random por tipo
  • Cada minijuego sync opcional → games + history_games en PG

Algoritmo de layout — nodos sobre Path2D

En MapBoard, al cargar el mapa se lee layout del JSON y se resuelven posiciones sin editar cada nodo a mano en runtime.

celiaquia_mapa.json → layout.route_id + placement_mode ↓ MapRouteRegistry → NodesContainer/Rutas/<route_id> ↓ MapPathLayout.resolve → anchors (1 punto = 1 nodo) | curve (reparto por largo) ↓ MapBoard → visual.position = posiciones[i]
MapBoard.tscn · layout automático Rutas/RutaCeliaquia1 · placement_mode
Cómo se aplica
1

El JSON trae layout.route_id → Godot busca el Path2D en NodesContainer/Rutas/.

2

En el editor trazás la curva: cada punto Pn del Curve2D es un anchor del mapa.

3

MapPathLayout.resolver() calcula un Array[Vector2] con una posición por nodo del JSON.

4

MapBoard asigna visual.position = posiciones[i] — sin mover nodos a mano en runtime.

5

Con debug_layout=true ves círculos rojos con índices (mismo criterio que P0…P5).

anchors 1 punto = 1 nodo

calcular_por_anchors() — posición i = curve.get_point_position(i). Ideal cuando editás la curva nodo a nodo en Godot.

curve reparto por largo

calcular_por_curva() — reparte N nodos entre start_margin y end_margin sobre get_baked_length(), aunque haya más nodos que puntos.

Path2D / Curve2D Anchor Pn (punto editor) Nodo Nn (nivel_id) Margen (solo curve) Celiaquía usa placement_mode: "anchors"

Modos: anchors alinea cada nodo a un punto de la curva; curve reparte equidistante con márgenes. Ver juego/mapas/README.md.

Infra · E3 → E4

Migración e integración con Supabase

Express sigue para CI local; staging/producción apuntan a Postgres managed + Edge Functions. El flujo de partida no cambia: primero save, después sync.

Qué migramos

  • Esquema MER → migraciones BACKEND/migrations/
  • Auth, progreso, games, streaks, leaderboard → tablas PG
  • Contenido educativo fuera de la DB (sigue en JSON en Godot)
  • Setup: npm run setup:supabase · migrate:supabase

Cómo juega Godot

  • backend.local.json → api_mode: supabase_edge
  • Edge: auth-login, progress-save, player-me
  • E4 suma: verify-email-*, internal-job (cron)
  • Sin red: save + cola backend_sync_queue.json intactos
Pipeline staging integrate:staging supabase:functions:deploy setup:supabase:cron sync:godot-config:staging · local-first no se negocia
